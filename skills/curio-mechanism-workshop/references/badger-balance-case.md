# 双獾药秤案例摘要

用于说明复杂圆雕的降面、UV 与贴图衔接。完整图片和统计见 [公开案例](https://github.com/wss534857356/curio-asset-skills/blob/main/examples/badger-balance/README.md)；源模型与游戏代码不随技能安装。

## 实际制作链路

1. 只生成一只独立獾雕高模。底座、刀口座、梁、链吊盘、游码和砝码用代码建模，保留准确接口。
2. 单獾 1,342,390 个三角形经 Remesh 得到 5,212 个三角形，再执行 UV Unwrap。任务目标不能代替实际下载计数。
3. R01 从高模向新 UV 中模烘焙 1K 切线法线与其他材质图；UV 变了，旧贴图不能直接套回。
4. R02 为改善纹路与材质身份，复用 UV 模型做 Retexture，再修正铜材质响应。最终 R02 使用这套贴图，不把 R01 烘焙法线说成最终材质来源。
5. 同一獾 mesh 镜像复用到另一侧，与代码机构组装。整件近看预算含实例为 28,120 个三角形，陈列版为 3,934。
6. 四种运行模型共用 5 张纹理，连图标共 9,801,228 字节。贴图占约 69.2%，因此几何降面与贴图预算分别处理。

## 使用这个例子时保留的区别

- 单部件和整件计数分开；存储一份 mesh 不代表两个实例只绘制一次。
- UV 属性存在不证明布局、拉伸或配准合格；同面数也不保证旧纹理仍适用。
- 高模、UV 白模、R01 烘焙版和 R02 贴图版分别记录，不将所有历史步骤包装成同一最终材质的来源。
- 近看中模与陈列 LOD 保持支撑、尺度、语义节点和有效接口。
- 本例历史 Meshy 消耗为生成 20、Remesh 5、UV 5、Retexture 10，共 40 积分；只是实际记录，不是当前价格或未来预算承诺。

公开案例于 2026-09-26 重读资产与任务文件；游戏截图和功能记录来自之前制作，不代表发布案例时重跑了整套游戏。
