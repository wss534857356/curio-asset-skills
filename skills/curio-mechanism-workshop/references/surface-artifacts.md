# 表面碎线、裂纹感与过重描边

用于藏品进入游戏后出现三角网格感、碎片感、额外接线或密集黑线，而原模型或常规 PBR 预览看起来较平顺的情况。先定位显示链路中的原因，再决定是否改网格；这不是所有模型统一降低描边的规则。

## 在同一条件下做对照

固定模型版本、姿态、相机、缩放、光照和曝光，保留原样截图。按症状选择对照，每次只改变一个因素，不必机械地全部执行：

| 对照结果 | 优先检查 | 对应处理 |
| --- | --- | --- |
| 关闭描边后，三角裂纹或接线大幅减少 | 深度曲率、面内折线阈值与强度 | 降低细小折线，保留物体外轮廓和有意义的深度断层 |
| 降低／关闭法线贴图后改善 | 法线强度、切线基、UV 接缝、烘焙匹配 | 修正材质或法线流程；区分顶点法线和法线贴图 |
| 关闭接收阴影后改善 | 自阴影精度、偏移、投影面设置 | 调整对应阴影路径；核对实际阴影贴图已刷新 |
| 白模、普通着色下仍有真实裂口或轮廓缺损 | 开边、重复面、相交、破损几何 | 做局部网格修复，保留有意的开口和构造接缝 |
| 只在远观版、特定距离或缩放下出现 | LOD、纹理缩小采样、屏幕空间阈值 | 核对对应模型和实际视距，不直接修改近看原件 |

关闭描边只是诊断，不自动作为最终效果。正常雕刻、宝石切面、齿轮边界和鉴别线索不能一并抹去。白色表面若仍丢失体积，还应单独看曝光、材质与光照。

## 描边是主因时

优先区分三类线：物体外轮廓、较大的深度断层、表面的小折线。只减弱造成碎裂感的部分。下面是项目自定义后处理的示意，不是 Three.js 内置接口：

```glsl
float edge = max(silhouette,
                 max(discontinuity * 0.95, crease * creaseOpacity));
```

- 用现有物件 ID、材质标签或检视模式选择强度；少量物件不必引入新的通用渲染框架。
- 参数只能作为调试起点。一个案例中的 `0.45 → 0.06` 不代表另一种描边算法也该用相同数值。
- 若参数控制整个屏幕，当前检视背景也会受影响。说明这一范围，并在退出、看文书、收柜或换工件时恢复默认值。需要真正按物件／材质隔离时，再评估遮罩或单独渲染通道。
- 普通 uniform 调整不需要每帧重建材质或设置 `needsUpdate`。如果实现涉及新的 pass、材质分支或光源配置，再按 [首次交互性能](first-interaction-performance.md) 检查实际成本。
- 原 UV 和贴图可用时，不因为显示碎裂就自动调用 Remesh、重新展开或重新贴图。

## 已有案例与边界

在一套 Three.js 0.185.1 的 Noir 工坊中，白狼念珠匣和兔女舞匣都有细碎面线。白狼匣关闭描边后改善明显，关闭法线贴图或接收阴影则没有消除三角线；舞匣的同机位对照也支持降低面内折线。

这两类检视采用了 `0.45 → 0.06` 的曲率折线强度，保留轮廓与深度断层，沿用原模型、UV 和贴图。双鹭渡签盒的描边对照随后也支持采用同一轻折线设置；开盖、倒签与装回仍需核对。每个新物件都看实际对照，不仅凭名字或“Meshy 来源”套用。

这证明的是特定显示问题得到改善，不代表模型已焊接、几何变光滑或拓扑完全无缺陷。若确实需要改变形体，再对局部做保形平滑／修缝；保护毛发尖、羽缘、荆棘、锁扣、孔洞及装配面。保留原 UV 是否足够，要结合变形范围和烘焙贴图再检查。

## 最小验收

看同机位前后图、正常尺寸与一个有代表性的放大视图。核对轮廓、雕刻和操作高亮仍可读，真实点击或一个相关维修步骤可用；检查退出和切换后参数恢复，普通物件没有继承弱折线。

保存实际模式、倍率和改动范围；以运行数据／画面为准，不从截图文件名推测。无需因一个显示参数变化重跑无关剧情或重新制作全部资产。
