# 运行资产、LOD 与像素图标

出现三角网格感、额外接线或碎片感时，先按 [表面碎线诊断](surface-artifacts.md) 区分渲染与几何原因，再决定是否改模型或 UV。

处理首次点火、开灯或切材质卡顿时，读取 [首次交互性能](first-interaction-performance.md)。其中包含灯光数量变化导致的新着色器组合、提灯修复案例及冷页面验证方法；普通静态资产交付按本页原有范围执行。

## 建议预算

先看项目和目标设备。下面仅为这类桌面藏品的起点，按实际剪影与性能调整；面数均指最终三角形，不是 API 的四边面数。

| 用途 | 起始目标 | 重点 |
| --- | --- | --- |
| 程序结构件 | 每件几十至 2,000 三角形 | 必要倒角、接榫和机械轮廓 |
| 中模完整检视／维修 | 整件 10,000–35,000 三角形 | 活动部件独立；装饰细节烘焙到法线 |
| 远观／展柜／摆件 | 整件 1,000–4,000 三角形 | 游戏实际屏幕大小下仍有辨识度 |
| 运行贴图 | 通常 1K；重要近看表面可 2K | 重用材质，按字节数与实机效果验收 |
| 图标 | 原生 64×64 RGBA；必要时另做 32×32 | 透明背景，小尺寸可辨认 |

图标、纹理和 Meshy 面数预算互不替代。1K/2K 为游戏导出目标，不意味着 Meshy 所有端点接受这些生成分辨率。源贴图可更高，交付前使用项目允许的转换工具整理。

## 贴图与装配

- 盒板做规则 UV，长条沿长度布置木纹，端面另映射；同材质保持相近 texel density。独特铭文与真假线索使用独立小图集或材质区域。
- 中模 UV 查看 checker、接缝、翻转、过度拉伸和 atlas 边距。共享重复纹理允许有意重叠；独特烘焙区域不应意外重叠。
- 高模烘焙时分件或用匹配 cage，避免相邻零件把阴影／细节烘焙到彼此上。保留孔洞与影响剪影的几何，烘焙表面雕刻。
- 检查颜色空间、金属度、粗糙度及法线方向，GLB 实际引用到相应贴图。在游戏灯光下查看，不仅看 Blender 渲染。
- 远观 LOD 可以合并不动的外壳，但 root、支撑面和变换保持一致。需要动画的陈列物继续保留对应运动部件；不能把维修状态中的零件丢掉。

## 图标画法

用户的“类怪物猎人”指背包素材／藏品的辨识方式：简洁轮廓、明确材质分区、有限颜色和像素簇；依据本项目新物件画原创图标。

从最后验收的完整／关闭状态渲染一张清楚的三分之四视图作为参考。打开状态更能表达特征时可选打开，但必须与游戏中可达到的状态一致。视图、物种徽记、零件数和主材质保持一致。

ImageGen 提示词示例：

> 为参考中的同一件黄铜与胡桃木短曲匣绘制原创像素风背包藏品图标。保留盒盖的猫头鹰浮雕、箱体比例和右侧上弦柄。三分之四视角，整体轮廓完整，主体留少量透明边距，深色一至两像素轮廓，清楚的像素簇，约 16–24 色，金属用少量明暗色块表达。追求经典狩猎游戏素材图标的小尺寸辨识度。真实透明背景，无文字、无图标边框、无地面投影、无发光光晕，不画细碎噪点。

使用 ImageGen 绘制和视觉修订；精确网格、色板及导出复用用户已授权的 `noir-pixel-art` 处理流程或项目图标工具。生成大图不是原生像素尺寸保证。若该处理工具不在项目中，按本轮授权范围进行格式规整并记录方法，不能声称一个未导出的 64×64 文件存在。

同时查看真实 32／64 像素显示，以及 nearest-neighbor 放大图。缩小后模糊时，重画大色块、简化内部装饰，不只是重复锐化或量化。检查 alpha，棋盘格不能烙在图内；不用渲染截图直接缩小冒充画好的像素图标。

## 目标项目接入

定位模型工厂、交互控制、维修状态、藏品登记及打包入口，再做职责映射：

- 模型根节点提供部件集合、控制器、更新与释放入口；交互绑定真实 mesh、任务 ID、操作类型和局部点击点。
- 精细网格替换粗模后保留稳定接口并重新核对拾取，不能让点击点留在空洞或被外壳遮挡。
- 保护配合区域、转轴与运动范围，同时保留已完成的可见器形，不以技术占位块覆盖美术部件。
- 沿用原有任务顺序、加工和试用状态，外观更新不重置玩家进度。加工期间镜头稳定，当前可操作件高亮。
- 维修镜头遵守目标项目的桌前边界；含 2.5D 人物的场景不默认整圈绕拍，离线仍需查看工件背面。
- 核对 UI 实际读取的模型与图标字段。异步加载应处理成功、失败和释放，再开放交互。
- 核对构建资源清单，确认新 GLB、贴图和图标进入实际发布包。原游戏适配代码不包含在本技能中。

## 文件与验收

作者用高模、原始 Meshy 下载、`.blend` 和重建缓存放仓库外既有资产归档位置；临时检查图用项目忽略目录。仓库保留必要的脚本、规格、来源记录、最终运行模型与共享贴图，避免把每个状态复制一整套 4K 贴图。

建议交付：`mechanism-spec.json`、建模／适配代码、`mid.glb`、`display.glb`、贴图、`icon-64.png`（及需要的 32px 版）、简短资产清单。清单登记本地路径、实际面数／文件字节、关键节点、来源任务和检查结果，不将带凭据或已过期的下载地址当成永久资源。

辅助检查例子（脚本路径相对本 skill）：

```text
python scripts/inspect_glb.py mid.glb --max-triangles 35000 --require-node ROOT --require-node LID_PIVOT --require-uv
python scripts/inspect_glb.py display.glb --max-triangles 4000
```

脚本检查 GLB JSON 的结构计数、命名及 UV 属性存在性，包含实例的保守预算；不解码实际顶点，不证明 UV 无拉伸／无重叠、流形、接缝精度或装配行为。另用 Blender 重导入和原游戏运行检查这些内容。

验收按变化范围：整体／背面／开盖，活动件始末位置，拆装与加工，真实网格点击，近看／远观切换，图标在背包中的实际尺寸。运行项目所需构建；无需因单件美术替换重跑未受影响的所有章节。

清单中分别说明形体还原和功能检查的结果，并给出概念图与相近角度实机图的路径。美术验收按 [器形还原](visual-fidelity.md) 进行，面数和 UV 检查通过不能代替它。
