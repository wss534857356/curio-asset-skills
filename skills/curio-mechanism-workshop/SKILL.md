# 机关藏品制作

把一件能解释运作方式的机关，做成可拆装、可维修、可近看，也能远观陈列的游戏藏品。外形、机构和操作来自同一份部件规格；好看的概念图不代表机关已经能工作。

## 先确定交付范围

- 按用户要求做方案、指定阶段或完整资产。仅要求创建 skill／写方案时，不启动 ImageGen 或付费 Meshy 任务。要求完整制作时持续做到游戏接入和图标交付。
- 查看当前项目的资产登记、已有玩法、模型及源文件存放约定。优先复用尺寸、转轴、材质和控制逻辑，不为换外观重写剧情或维修流程。
- 拆件后要让玩家沿蓝图加工毛坯、合形换标准件再手动复装时，配合 [curio-part-finishing](../curio-part-finishing/SKILL.md)；连续去料、轻吸附和报废购料不能退化成区域点击计数。
- 复用玩法接口不等于保留粗模外形。完成品要落实概念图中的器形、比例和构造层次；贴木纹、加少量倒角或附上一尊雕像，不能单独证明整个工件已完成美术制作。
- 先判断细节需要表面凹凸还是立体体积，再选工具。像短曲匣盖内的猫咪浅浮雕，默认走 ImageGen + 高度／法线纹理；完整复杂工件、守夜鸦提灯这类要多角度观察的立体造型，才优先用 Meshy。简单盒体即使是一件完整器物，仍可直接代码建模。
- 将概念图与图标交给 `imagegen`；Meshy 操作使用已安装的 `meshy-3d-generation` skill，读取其当前 setup、pipelines、delivery。不要依赖某个插件缓存版本的绝对路径。
- 记录已授权的制作阶段、输入和积分预算。已授权的阶段连续完成，不逐步重复询问；额外付费重试或超预算按 Meshy 插件规则处理。

## 1. 方案与机关

先写 `mechanism-spec.json` 和简短制作方案，至少包含：

- 藏品用途、外形尺寸、文化与人物归属、材质、故障及修好后的表现。
- 选中外观参考及其形体特征：主轮廓、盖底比例、边框截面、支脚、面板凹凸和有辨识度的构件；分别指定几何或表面贴图的实现方式。
- 力或运动怎样传递；玩家拆什么、用什么工具、加工哪里、如何判断成功。
- 部件 ID、父子关系、制作路线、尺寸、支撑面、装配接口、转轴、行程、拆卸方向。
- 完整／损坏／拆开／修复状态，以及触发动作、前置条件和可逆行为。
- 近看中模、远观低模、贴图和图标预算；输出及作者源文件的位置。

用 [机关设计规则](references/mechanism-design.md) 推敲关系，可从 [规格示例](assets/mechanism-spec.example.json) 改起。示例是制作规格，不是通用生成器或已实现的藏品。

方案要能指导建模：写“钥匙转动带动偏心轮，推动锁舌退出槽口”，不要只写“神秘精巧的机关”。普通艺术与尺寸选择自行确定；只有影响玩法目标的缺失信息才需要澄清。

## 2. ImageGen 概念图

先生成整体概念图，明确轮廓、主材质、构件比例及开启方式；必要时补同一设计的打开状态或结构剖示图。查看实际图像，修正与规格冲突的地方后再进入建模。

外观制作时读 [器形还原与美术验收](references/visual-fidelity.md)。已有方盒原型是机关尺寸参考，只有设计确实需要时才把“长方盒”写成外形约束。不同人物的藏品应有合适的器形和构造差异，不仅更换颜色或顶上的装饰。

- 整体审阅图可有结构标注或分解关系；送给 Meshy 的图必须是单一目标部件、完整入画、无标注、无桌面／手／展示底座。
- 先确定整体再拆部件参考，保持同一风格、厚度和纹样。多视图必须是同一个物件，不能把几种设计混作不同角度。
- 已有概念图符合本轮规格时复用。局部缺陷只修相应部件，不反复重生整件。
- 保存实际提示词、参考图用途和选中的生成文件；图片不能只存在临时生成目录。

## 3. 可操作粗模

通过 Blender Python 或项目已有 Three.js 构造器生成粗模，完成分件、安装点、转轴和运动。先跑通完整操作，再用精细外观替换相应部件。

| 部件 | 首选制作方法 |
| --- | --- |
| 盒体、背板、木条、皮带、普通支架 | 代码建模；按概念图使用截面挤出、曲线、旋转体、切角、凹槽和有屏幕可读性的倒角，再复用贴图 |
| 轴销、齿轮、锁舌、滑轨、接榫、咬合面 | 按尺寸代码建模；运动与装配精度优先 |
| 盖内猫咪浅浮雕、牌面徽记、刻花、压纹和木板花纹 | ImageGen 底色及配准的高度／法线图，贴到有厚度和倒角的简单载体上 |
| 圆雕兽首、独立摆件、完整复杂工件、守夜鸦提灯式主体 | Meshy 生成可多角度观察的立体外观，再拆出活动件和装配接口 |
| 明显改变剪影、存在真实镂空或较大突出体块的部件 | 代码或 Meshy 保留必要体积；精密孔、滑轨、运动结构仍按尺寸制作 |

盒体与长条默认展开规则 UV：面投影、箱形或圆柱映射；保持木纹方向、纹理密度和端面。不要给每根木条另生成一张大贴图。引擎里使用了三平面材质，不代表导出的 GLB 已带可用 UV。

浅浮雕不因图案复杂就升级为 Meshy 高模。按 [浅浮雕材质流程](references/surface-relief.md) 制作并在游戏侧光、斜视和目标缩放下验收；只有贴图无法表达的轮廓、厚度、镂空或独立运动部分才增加几何。

粗模完成只证明玩法与接口可用。精修外壳时对照概念图重建主形和次级构造；关键孔轴保持参数化，曲面外壳或复杂立体构件可单独走 Meshy 后修整装配面。稳定节点和任务 ID 不应限制可见网格的形体替换。

## 4. 精细部件与拆分重做

仅对 BOM 中确实需要立体造型的 Meshy 部件生成，优先使用整体或该部件的概念图。浅浮雕、刻花等留在贴图路线，不进入付费模型任务。首次只做足以验证形体的生成，材质阶段按已定方案安排。

检查轮廓、背面、厚度、镂空和装配区域。如果单件存在粘连、细长件变形或比例失控，先判断能否本地修复；需要重做时，按真实接缝拆成有意义的部件分别生成，然后装回粗模接口。

- 例如守夜鸦提灯可按实际结构拆为“立体鸦身灯座、笼架、可开灯门、提环”；普通框架可以代码制作。不要将平面浅浮雕的猫与两侧花纹拆成多个付费模型任务。
- 盖、底、铰链等存在相对运动的件始终独立；在 API 优化前保留分件。不要把整台机关一次 remesh 后期待仍有原来的节点、空腔和转轴。
- 每个回传模型独立校准尺寸和朝向，记录装配变换；不要逐件自动归一化后凭视觉拼接。
- 一轮问题先定位到具体部件。预算内的拆分任务按计划执行；没有预算支持的新增生成先报告，不无上限试抽。

## 5. 中模、UV 与贴图

Meshy 立体形体通过检查后，用其 Remesh API 经插件 CLI 生成中模，再处理 UV 和最终贴图。纯代码／贴图部件直接整理本地 UV、材质及 LOD，无需为走完流程调用 Meshy。具体命令、API 限制、失败回退见 [Meshy 制作流程](references/meshy-pipeline.md)。

需要实际案例时读 [双獾药秤](references/badger-balance-case.md)：单獾高模降面、UV 重排、R01 烘焙与 R02 贴图修正，最后装配并派生陈列 LOD。区分单件与整物统计，以及每一版真正采用的材质来源。

- “请求 20,000 面”不等于实际输出 20,000 面。下载后测量；分别记录 API 面数、导出三角形数和实例数量。
- 优先对独立外观件优化，保留代码结构、接口及转轴；中模是可维修的游戏资产，不只是低面数雕塑。
- 简单几何保留代码 UV。复杂件使用 Meshy UV Unwrap；不可用时在 Blender 展 UV。
- UV 重排后重新烘焙或贴图。保留高模／旧贴图作为烘焙来源，不能把旧贴图直接套到新 UV。
- 纹理应为可受游戏灯光照明的材质；将雕刻小细节烘焙进法线，保留影响剪影的几何。

## 6. 远观模型与藏品图标

由验收过的中模派生远观／摆件低模，保留轮廓和主要材质。陈列时可合并静止件，检视和维修时切回有语义节点的中模；切换前后底面、尺寸与朝向一致。

再基于最终藏品的固定角度渲染，用 ImageGen 制作原创、怪物猎人式背包藏品的像素图标：轮廓清楚、材质分色、少量高光、有限色板、透明背景。图标跟随最终模型，不继续沿用已经淘汰的概念造型。

尺寸、LOD 预算、UV／贴图检查、图标提示词和项目接入见 [交付与图标](references/runtime-and-icons.md)。

## 7. 验收与交付

- 新增或改动点火、开灯、切材质等运行时交互时，核对首次操作、复位与再次操作。出现首次卡顿时读 [首次交互性能](references/first-interaction-performance.md)，按编译、资源准备和持续渲染成本分别取证。
- 外形与玩法分别验收：先比较概念图和最终模型的相近视角，再看无贴图形体、游戏 100%／200% 实机效果。轮廓或构造明显缺失时继续修形，不能用面数、UV 或流程测试通过代替外观验收。
- 在 Blender 或对应工具中检查实际装配，再在游戏运行时验证准确的导出文件。查看整体、背面、打开和拆件后的画面。
- 逐项检查运动极限、拆装顺序、对位、零件之间的穿插及点击遮挡；缩放到实际游戏尺寸和 200% 再看细节。
- 物件由桌面或夹具真实支撑；用靠近、略微俯视的工作台镜头提高可读性。当前可操作件高亮，加工期间镜头稳定。
- 用 [GLB 元数据检查脚本](scripts/inspect_glb.py) 查看三角形预算、UV 属性和必要节点；脚本结果不能代替 UV 拉伸、模型外观或真实拾取验收。
- 按阶段交付路径、已验证内容、实际积分／未知项及剩余缺陷。未运行的付费阶段、未查看的图像和未测试的游戏接入不能标为完成。

常见调用：`使用 $curio-mechanism-workshop，把卡珊德拉的短曲匣做成精细可维修藏品，沿用现有音梳与发条流程，交付中模、远观版和像素图标。`
