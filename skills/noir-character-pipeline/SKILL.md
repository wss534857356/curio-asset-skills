# Noir 人物与法线制作

把人物设定变成能在游戏里重新打光的立绘。标准交付包含底色、轮廓遮罩、专用形体法线，以及适用时的材质分区、项目配置和工作台对照。沿用用户确认的风格；当前默认是中世纪动物拟人、美漫粗黑描线、红蓝赭橙大色块，保留高清插画尺寸。

## 确定本次范围

- 新人物：从角色设定开始，完成本次要求的素材和接入。只要概念图时，交付概念图即可。
- 补法线或调整材质：复用现有角色的身份、彩图、姿态和遮罩，只制作缺失或需要修正的部分。
- 确认角色 ID、物种、年龄段、服装、携带物、表情、构图、出场位置。优先读当前设定和实际图片；历史提示词可能是弃稿，不能反向改写已经确定的角色。
- 先定位当前项目及其资产清单、人物配置、材质和工作台。读取 [项目接入说明](references/integration.md)，核对目标项目自己的通道与渲染约定。
- 人物立绘使用平面承载，法线提供固定视角下的形体感；需要真实侧面、转身或骨骼动作时，另行处理对应的三维或动画需求。

## 素材约定

| 素材 | 内容与约定 |
|---|---|
| Albedo | 材质本色与必要结构描线，sRGB；去除定向高光、投影、橙色轮廓光和 AO 黑块 |
| Opacity mask | 人物及随身物白、空隙与背景黑；保持手指、耳、尾和衣摆轮廓；使用真实 alpha 或已核对的独立遮罩 |
| Form normal | 独立估计头、口鼻/喙、躯干、四肢和主要衣褶的方向，OpenGL +Y 切线空间，线性 RGB；正面中性值约为 `(128,128,255)` |
| Material map | 根据实际 shader 定义编码；本流程示例为 R=轮廓响应、G=高光权重、B=粗糙度，**不是 ORM** |

- 所有图对应同一张实际画布、姿态、比例和像素位置。默认新画布约 1024×1536；已有素材以实测尺寸为准，包括非整齐尺寸。尺寸相同并不证明轮廓和五官对齐。
- 法线不来自彩图亮度：豹纹、羽色、鼻子本色、墨线与画出来的阴影不是凹坑。优先宽而平滑的形体，少量真实接缝和配件倒角，避免把毛发变成碎亮点。
- 法线与材质图是数据，采用 `NoColorSpace`；所有图的 UV/翻转与彩图一致。不要为修复某次反光随意翻转绿色通道。
- 这些生成的法线是依照插画估计的形体数据。除非实际使用三维模型烘焙，不标记为 baked、扫描法线或物理重建。

## 制作顺序

1. **固定角色原画。** 先查看当前原图和风格参考，分别标明编辑目标、身份参考、风格参考。新人物生成平光底色；已有彩图含重光影时，先做保持轮廓和五官位置的去光照版本。保留毛色与必要描线，不把“去阴影”变成换衣服或换物种。
2. **确认遮罩。** 检查真实 alpha，画出来的棋盘格不算透明。已有可用遮罩就复用；缺少时制作独立黑白 silhouette matte，确保随身物也在里面，肢体间真实空隙保持为空。
3. **生成专用形体法线。** 以固定后的彩图为编辑目标，遮罩为位置约束，已验证的其他人物法线仅作编码与平滑程度的参考。逐人物、逐素材生成，不能把另一人物的正常贴图接到新身份上冒充专用图。
4. **按需制作材质分区。** 用户要求，或角色含需要不同响应的布料、毛发、皮革和金属时，输出匹配通道定义的材质图。仅补法线的任务可以保留通用材质响应，并说明这一点。
5. **归档并接入。** 将选用文件保存到项目中，保留原图与实际生成提示词、各输入的角色、输出来源、尺寸和版本。运行路径不能指向生成工具缓存。对旧角色优先保留可用回退，不把兜底法线标为专用图。

生成时读取 [可复用提示词](references/prompts.md)，根据实际人物替换角色描述和形体重点。使用当前可用的内置 ImageGen，并遵循其当前参数约定；当地文件先用 `view_image` 查看。若环境提供 imagegen skill，可使用它处理工具调用。不要在提示词或记录里臆造一个不可选择、未返回的模型版本。保持每张图的参考对象明确；只补法线不需要重新生成整套资产。修订针对看见的问题，优先修复错位或烘焙阴影，而不是不断加大法线强度。

## 检查与调光

先运行只读检查脚本（依赖 Pillow），它只输出检查结果，不修改图片：

```text
python <skill-dir>/scripts/check_character_maps.py --albedo <color.png> --mask <mask.png> --normal <normal.png> --report <pixel-check.json>
```

有材质图时加 `--material <material.png>`；没有独立遮罩且渲染器直接使用彩图 alpha 时可省略 `--mask`。脚本检查尺寸、有效轮廓、法线方向变化及编码异常；不能判断脸是否对齐、风格是否合格或法线是否准确。

在实际人物工作台检查相关部分：

- 同一角色、机位、贴图、曝光：normal OFF / ON，再只反转主光的 X。脸颊、口鼻和衣褶的明暗应随灯移动，毛色、描线和轮廓位置应稳定。
- 查看法线方向、主光灰度和最终成图。错位、反向突起、描线凹陷、塑料高光和颗粒噪声分别修复；不要用模糊整张彩图来掩盖法线噪声。
- 赛璐璐对照的两侧使用同一法线，仅改变 N·L 分档。保留彩图和灯色；不能用黑白阈值后处理代替法线明暗二分。
- 接入游戏时检查真实入口、桌沿/门窗遮挡及室内外曝光；人物使用同一组世界空间灯光。若场景有动态炉火，确认它实际影响人物，白天熄火时人物无残余火光。
- 新增接入路径时检查正常加载与缺法线回退。不要通过修改玩家存档完成美术测试；用不持久化的工作台或隔离浏览器。

复用项目的材质、配置与工作台，不再创建第二套人物 shader 或硬编码另一份人物清单。图像尺寸不因想增强立体感而自动加倍；先调低频形体、法线 mip 与光向。静止、不投影的立绘加载不应触发全场阴影重绘。

只改素材时检查文件与真实成图；改了 TS/渲染绑定则运行项目构建，涉及剧情逻辑时再运行对应逻辑检查。机器通过与审美确认分别报告。

## 交付

提供最终资产完整路径、提示词/来源记录、工作台地址和实际对照结果。说明只完成了补法线、完整材质，还是游戏角色接入；缺图回退、未完成的生成或未完成的视觉检查应如实写出。用户要求完整接入时继续完成加载与工作台验证，不停在概念图。

示例：`$noir-character-pipeline 给现有雪豹补一张更有面部体积的法线，保持原画和遮罩不变，并做左右光对照。`
